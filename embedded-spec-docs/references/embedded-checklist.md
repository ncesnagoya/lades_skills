# 組込み開発チェックリスト（正しさ・実機検証）

設計レビュー・コードレビュー・品質チェックの際に参照する、組込み固有の観点集。
一般的なソフトウェアレビューでは見落としやすく、組込みで実害が出やすい項目に絞っている。

## 1. 正しさ（組込み固有バグの観点）

### メモリ可視性・順序
- **volatile 正しさ**: MMIO レジスタ、ISR とメインで共有する変数、スピンウェイトのフラグには `volatile` を付ける。逆に不要な `volatile` で最適化を無駄に阻害していないか。
- **メモリバリア / 順序**: MMIO 書き込みの順序保証（DMB/DSB/ISB）、コンパイラバリア、デバイスの順序依存（設定→有効化の順）を確認。
- **アトミック性**: ISR と共有する変数の read-modify-write、複数バイト変数の非アトミック更新（更新途中で割り込まれる）。

### DMA・キャッシュ・アライメント
- **キャッシュ整合**: DMA バッファは送信前フラッシュ／受信後インバリデート、または非キャッシュ領域に配置。
- **アライメント**: DMA バッファ・ディスクリプタをキャッシュライン境界に。アンアライメントアクセス禁止アーキ、`packed` 構造体のアクセスに注意。
- **バッファ所有権**: DMA 実行中に CPU 側が触らない／逆も同様。

### 割り込み・並行性
- **ISR 安全性**: ハンドラは最小限、再入可否、ISR から呼べない関数（`malloc`/`printf`/ブロッキング API）を呼んでいないか。
- **共有データ保護**: クリティカルセクション／割り込み禁止区間の最小化、優先度反転、デッドロック。
- **競合**: メインループと ISR、コア間（マルチコア）でのデータ競合。

### 数値・ビット・移植性
- 整数の符号・幅・シフトのオーバーフロー、ビットフィールドの移植性、エンディアン依存。

### リソース制約
- **ヒープ**: 動的確保の可否（多くのベアメタルで禁止/限定）。確保失敗の扱い。
- **スタック**: 最深 ISR ネストを含めたサイズ見積り、再帰の有無、巨大なローカル配列。
- **コードサイズ**: ROM/Flash 制約。

### C++ 固有（使う場合）
- 例外 / RTTI の有効・無効方針との整合、グローバルコンストラクタの初期化順序依存、`static` ローカルの初期化（threadsafe-statics 設定）。

### 初期化・タイミング
- **初期化順序**: クロック → 電源 → ピン → ペリフェラルの順序、リセット解除待ち、PLL ロック待ち。
- **タイミング**: ビジーウェイト/ディレイの根拠（クロック前提が正しいか）、ウォッチドッグのキック、リアルタイム期限。

## 2. 実機検証（printf が無い前提の確認手順）

- **ビルド**: 警告ゼロ。`size`/map ファイルで ROM/RAM 使用量を確認。フォーマッタ適用済み。
- **静的解析**: 可能なら静的解析ツール／lint を通す。
- **ロード**: フラッシュ／SD／デバッガ経由で実機にロードできる。
- **デバッガ**: SWD/JTAG 接続、シンボル（elf）ロード、ブレーク／ウォッチポイント、メモリ・レジスタ・スタックの確認。
- **観測手段**: UART ログ、SWO/ITM トレース、LED/GPIO トグル、ロジックアナライザ／オシロ。
- **動作確認**: 期待動作（ペリフェラル出力・波形・レジスタ値）を実機で観測。正常系だけでなく境界条件・エラー経路も。
- **移植時の差分確認**: ボード変更時はクロック・ピン・UART・メモリ/DDR・デバイスツリー等の差分を確認。

## 使い方
- 設計（design.md）作成時: 関連する観点を設計に織り込む。
- コードレビュー / 実装時: 変更箇所に該当する項目を確認。
- 品質チェック（tasklist.md 完了条件）: セクション2を検証手順として使う。
