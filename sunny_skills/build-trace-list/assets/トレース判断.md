# トレース判断（人手管理）

機能に紐づけない `REQ-xxx` を、分類と理由つきで並べる。
`work/tools/trace_list.py` はこの表を読み、載っていない孤立 REQ だけを `ORPHAN_REQ` として報告する。

- 理由を必ず書く。空欄の行は読み込まない。
  理由: 理由の無い除外は「黙って除外」と同じである。空欄の行は `未分類` のまま赤になる。
- 理由は「なぜ機能に落ちないか」を一文で書く。
  「機能ではないため」のような同語反復を書いてはならない。
  同語反復かどうかは機械では判定できない。ここは人間のレビューに依存する。
- 分類は次の 3 語から選ぶ。`前提・環境条件` / `表記規約` / `その他`。
- 機能に紐づけると判断した場合、この表へ書かない。既に行がある場合はその行を消す。
  理由: この表は「現在、どの機能にも紐づけていない REQ」の集合である。
  紐づけた REQ の行を残した場合、`trace_list.py` の `STALE_JUDGMENT` が出る。
- 機能へ紐づけ直す場合、`work/functions/機能リスト.md` の
  `根拠 REQ` 列と `リファレンス` 列を直し、トレースリストを再生成する。
