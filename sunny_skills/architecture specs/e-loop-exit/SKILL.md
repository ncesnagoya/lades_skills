# E ループの終了判定

全体フローの文書 6章の E と 11章（全体ループの終了条件）を、手順とツールの呼び出しにしたもの。**正は全体フローの文書である。**
この skill と文書が食い違う場合は文書に従い、食い違いを `problems/` に記録する（skill は直さない）。

## 入力

- `work/qa/確認事項リスト.md`、`work/qa/確定事項リスト.md`、`work/means/実現手段一覧.md`、1〜5 の出力

## 手順

### 1. 設定のデータの表を組み立ててみる

工程 7 で値まで書く表（ルートの定義の入力・出力・写し方・周期、端子の割り当て、設定値・定数など）を、
`実現手段案.md` の「決める値と出所」と、出典・確定事項から、**行ごと・欄ごとに**組み立ててみる。

- 出典や確定事項から取れない欄が見つかったら、その値の不足を確認事項として登録する（発生元 `判定 E`、トレース情報に表・行・欄と関わる機能ID／全体条件ID・手段ID。確認先は分かれば付け、次の回の M4 で見直す）。
- 表は工程 7 の下書きであり、ここでは成果物にしない（組み立てて空欄を探すことが目的）。
- 理由: 工程 7 で表を値まで書いて初めて、欠けている欄が見つかることがあるため（ループの中で見つけて確認事項にする）。

### 2. 11章の終了条件を、全項目確かめる

```bash
python3 work/tools/check_completion.py e --round N
```

ツールは、機械で確かめられる項目を**全項目**確かめ、項目ごとに「満たす」か「満たさない n 件（ID）」を出す。
終了しないことが最初の項目で分かっても、**全項目の結果を見る**（途中で止めると、ほかの項目の漏れが終了する回まで見えない）。

| 11章の項目 | 確かめ方 |
|---|---|
| 1〜3 で未解決の不明瞭・情報不足がない | ツールの「未解決の確認事項がない」 |
| 3 の決める値と出所に `不足` が残っていない | ツール。あわせて手順 1 で見つけた空欄 |
| 必要な技術参考情報が反映されている | ツールの「技術資料の確認事項がすべて 反映済 か 取下げ」 |
| 未回答の QA がない | ツールの「確認先 要求者 の未解決」 |
| 未完了の開発者検討事項がない | ツールの「確認先 開発者 の未解決」 |
| `回答済` の確認事項がない | ツール |
| 出典 → 機能ID／全体条件ID → 手段ID のトレースが維持されている | ツールの「M2」「M3」の検査 |
| 確認事項とその回答・検討結果を追跡できる | ツールの「J」の検査（相互参照） |
| `候補` の全案の要求者の判断が `要` / `不要` / `判断不要` のいずれか | ツール |
| 要求者が `不要` とした案がすべて `却下` | ツール |

### 3. 進む先を決める

- **すべて満たす** → M6 へ進む（要求者への提示は行わない。この回の `QA表_第N回.xlsx` は記録として残す）。止まらずに M6・M7 を続ける。
- **満たさない項目がある** → H1 社内レビューの前で止まる（手順 5）。
  - 満たさなかった項目のうち確認事項に無いもの（手順 1 の空欄、ツールの M2・M3・J の `[不足]` で確認事項になっていないもの）は、
    確認事項（確認先 `開発者`、発生元 `判定 E`、トレース情報に満たさなかった項目）として登録する。
  - **同じ回の中で 1〜5 をやり直して解消しない**（8章）。次の回で直す。
- 未回答の QA と、要求者の判断待ち（`未提示` `判断待ち`）の案が残っている間は、M6 へ進まない。進める必要があると判断した場合は、着手前に人間へ確認する。

### 4. 記録する

`work/PROGRESS.md` の「機能の実現手段一覧」フェーズの第N回の段（J と同じ場所）に書く。

```markdown
- 判定 E の結果: 終了しない（または「ループを終了した」）。11章の終了条件を全項目確かめた:
  未解決の確認事項 a 件（CQ-…）/ 技術資料 満たす / 未回答の QA b 件 / 開発者検討事項 c 件 / 回答済 0 / 値の不足 d 件（MN-… の …）/
  トレース（M2・M3）満たす / 追跡（J）満たす / 要求者の判断 判断待ち e 件（MN-…）/ 不要の却下 満たす。
  E で登録した確認事項: CQ-…（無ければ「なし」）
```

### 5. 止まる（終了しない回）

H1 社内レビューを依頼して止まる（7章）。報告に含めるもの:

- 社内レビューの依頼: 提示資料 `work/qa/QA表_第N回.xlsx`（「QA」「実現手段一覧」の 2 シート）と、まとめたレビュー資料 `work/means/レビュー/レビュー資料_第N回.html`
- 開発者検討事項（`開発者検討事項_第N回.md`）と技術資料依頼（`技術資料依頼_第N回.md`）。H1 であわせて答え・資料の配置を受けること
- 収束の状況（J の件数の前の回との比べ、M4 手順 6）
- E の結果（満たさなかった項目と件数）

止まった後は、人間が社内レビューの結果（フィードバックか承認）を示すまで再開しない。結果を推測で埋めない。

## 完了条件

進む先が M6 か、H1 社内レビューかに決まっている。11章の全項目の結果を記録した。

## してはいけないこと

- 最初に満たさない項目が見つかった時点で、ほかの項目を見ずに「終了しない」と決める。
- 満たさない項目を、同じ回の中で 1〜5 をやり直して解消する。
- 終了しない回に、社内レビューを飛ばして要求者へ提示する。承認前の提示資料を、要求者への質問として扱う。

## よくある誤り

| 誤り | 防ぎ方 |
|---|---|
| 未解決の確認事項がある時点で「終了しない」とし、値の欄の `不足` を確かめないまま回を重ねる | 手順 2。全項目の結果を見て記録する |
| 終了する回の確かめの途中で漏れを見つけ、同じ回の工程 3 で直す | 手順 3。確認事項にして次の回で直す |
| 表の形の値（ルートの写し方）の欠けが、工程 7 で表を書くまで見つからない | 手順 1。表を組み立てて空欄を探す |
