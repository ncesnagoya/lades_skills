- 次の工程: 本ノートの外。機能リストへの反映は `build-function-list` スキル（[SKILL.md](../../../../build-function-list/SKILL.md)）で行う

`F-ID` を新規採番してはならない。理由: 採番は台帳の責任である。`Q-ID` と同じ扱いとする。
既存の機能リストに該当がある場合は、その `F-ID` を使う。
既存に無い場合は `F-新01` のような仮番号にする。
該当する既存機能があるかを確認してから書く。
理由: 確認せずに仮番号にした場合、同じ機能が別番号で二重に立つ。
仮番号はこのノート内で閉じた採番である。
外部から参照する場合は「<主題> 解析ノート F-新01」と修飾する。
根拠 REQ をここに書いてはならない。正は機能リストとトレース表にある。

`未解決の論点` には、この機能候補の仕様が確定しない原因になっている ID を並べる。
書けるのは 2 種類である。3-b と 4-b の `A-ID`。
および 3-a の `I-ID` のうち、`確認` が次の 3 つのいずれかであるもの。
`未起票` / `起票済み（Q-xxx）` / `保留（Q-xxx）`。
無い場合は `—` と書く。

`主な根拠の分類` には、その機能候補の根拠になった主分類を書く。
`R1.1` のように、分類軸の階層番号まで書く。複数ある場合は `/` で並べる。
§2 で形成した下位分類（`送信監視` など）は書かない。

| F-ID | 機能候補（一言で）| 主な根拠の分類 | 未解決の論点 |
|---|---|---|---|

件数: n 件（うち既存 `F-xxx` に対応づけたもの a 件 ／ 仮番号 b 件）
全体に対する位置づけ: 全 N 件のうち a 件
母数 N は `work/functions/機能リスト.md` の正式な `F-ID` の件数とする。
分子 a は上の件数行の「既存 `F-xxx` に対応づけたもの」の件数とする。仮番号はどちらにも入れない。
母数は、この行を書いた時点の件数である。
理由: `F-ID` は飛び飛びに並ぶ。件数が無い場合、全機能がこのシートから出たと読める。
