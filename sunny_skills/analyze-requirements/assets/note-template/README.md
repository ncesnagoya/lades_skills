# <主題> 解析ノート

> テンプレの使い方。埋め終わったらこのブロックごと削除する。
>
> 1. このフォルダを `work/functions/analysis/<主題>/` へフォルダごとコピーする。`outputs/` も一緒に付いてくる。
> 2. `>` で始まる行は記入の指示である。埋めたら削除する。指示はすべて `>` で始まる。
>    記入するのは次の 4 つである。
>    - `<...>` で囲んだ箇所と伏せ字。実際の値に置き換える。
>      伏せ字は `REQ-xxx` `YYYY-MM-DD` と、`n 件` `a 件` のような英字 1 字と `件` の組である。
>    - `- 語:` の形の項目行。値を書く。既に値がある場合は書き換える。
>    - 表。行を足す。
>    - 見出しだけで本文が無い節。本文を書く。
>    書き換えてはならないのは、節の見出しと、上記のどれにも当たらない文である。
> 3. `` ` `` で囲んだ相対パスは、生成先の深さで Markdown リンクに張り直す。
>    理由: テンプレの置き場と生成先で、相対パスの深さが違う。
> 4. 工程の進め方・完了条件・止める条件は `analyze-requirements` スキルの SKILL.md にある。
>    このテンプレは記入欄だけを持つ。規則の正は持たない。

- 対象: `work/input/<ファイル名>`（シート／章）／ 可読版 `../../../input/converted/<ファイル名>.md`
- 採番範囲: `REQ-xxx`〜`REQ-xxx`（n 件）。採番方針は `../../README.md` にある。
- 更新日: YYYY-MM-DD
- 本ノートのフォーマットと作成手順は `analyze-requirements` スキルに従う。
  スキルの場所は `../../../../.claude/skills/analyze-requirements/SKILL.md` である。
- 分類軸（記述区分・R1〜R4）と評価観点（E1〜E4）の定義は
  `../GW要求仕様_要求分類・解析観点まとめ.md` に従う。

- 本文中の `§n` は工程 n を指す。工程記録 `0n_*.md` とその成果物 `outputs/0n_*.md` の対を指す。

  外部から参照する場合は「<主題> 解析ノート A-01」のようにノート名で修飾する。

## 内容の出所

## 内容照合の記録

`verify-against-source` スキルで正本と突き合わせた記録を書く。工程の完了を報告する前に書く。
原本が改訂された場合は照合をやり直し、この節も更新する。

| 項目 | 内容 |
|---|---|
| 照合したもの | <何と何を、どの種別で突き合わせたか> |
| 結果 | 記載事実の誤り N 件 |
| 見つかった問題 | フラグされていない解釈 N 件。<起票先と、是正した内容> |
| 限界 | LLM による照合は決定的ではない。再現性も無い。機械検証と同じ強度ではない。原本が改訂されたら照合をやり直す |

## 更新履歴

後工程（トレース・QA 反映など）でこのノートを直した場合は、必ずここに 1 行足す。
理由: 成果物は書き換えるため、変更内容は更新履歴と git 履歴にしか残らない。

更新履歴はノートで 1 本にまとめる。直したファイルは `対象` 列に書く。
理由: 各ファイルへ分散させた場合、ノート全体で何が起きたかを追えない。

本文の見出しに確定日または QA 番号を書き足してはならない。
`版` 列はノートの版（`v1` `v2` …）を表す。成果物の表に版は持たない。
