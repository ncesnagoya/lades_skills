# 書式の埋め方（`build-qa-sheet`）

本フォルダには、`build-qa-sheet` スキルが扱う書式の正を置く。
規則そのものは [../SKILL.md](../SKILL.md) にある。本ファイルは埋め方だけを書く。

## 置いてあるもの

| ファイル | コピー先 | 使う工程 |
|---|---|---|
| [QA-doc雛形.md](QA-doc雛形.md) | `work/qa/items/Q-00x_<主題>.md` | 工程 1 |
| [QAシート様式.md](QAシート様式.md) | コピーしない。列構成の正 | 工程 3・工程 5 |

`work/qa/QAリスト.md` の書式を本フォルダに置かない。
理由: あのファイルは `work/tools/qa_list.py` が生成する。書式の正はツールの中にある。

## `QA-doc雛形.md` を使うとき

1. 雛形のコードブロックを `work/qa/items/Q-00x_<主題>.md` へコピーする。
2. `Q-ID` は `Q-001` からゼロ埋め 3 桁の連番にする。既存の最大値の次を使う。
3. `元の論点` に `<ノートの主題> A-01` の形で書く。ノートの主題を省いてはならない。
4. `## 社内レビュー` 節は起票時には空にする。レビュー後に回次で追記する。
5. 起票したら `outputs/05` を更新する。
   **更新する欄を本ファイルに列挙しない。** `analyze-requirements` の
   [references/maintenance.md](../../analyze-requirements/references/maintenance.md)「QA を起票した場合」が定める。
   そこに書かれた作業をすべて行う。
   理由: 欄を列挙した場合、あちらに欄が増えたときに、この列挙だけが古くなる。

## `QAシート様式.md` を直すとき

列を足す場合と消す場合は、`work/tools/qa_sheet.py` の `COLUMNS` も同じ順序で直す。
一致は `python3 work/tools/test_qa_sheet.py` が検査する。
**片方だけを直してはならない。** テストが不一致で止まる。

列の順序を変える場合、`_WIDTHS` の並びも同じ順序で直す。
理由: `_WIDTHS` は列の位置で幅を決める。順序がずれると別の列の幅が当たる。

案件ヘッダの行数を変える場合、`HEADER_ROW` も同じ数だけずらす。
理由: `HEADER_ROW` は表の見出し行の位置である。案件ヘッダが伸びると見出し行も下がる。
