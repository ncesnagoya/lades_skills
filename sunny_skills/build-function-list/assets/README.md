# 書式の埋め方（`build-function-list`）

本フォルダには、`build-function-list` スキルが作る 2 つの生成物の書式を置く。
規則そのものは [../SKILL.md](../SKILL.md) にある。本ファイルは埋め方だけを書く。

## 置いてあるもの

| ファイル | コピー先 | 使う工程 |
|---|---|---|
| [機能リスト.md](機能リスト.md) | `work/functions/機能リスト.md` | 工程 3 |
| [item-template.md](item-template.md) | `work/functions/items/F-xxx_<機能名>.md` | 工程 5 |

既存の `work/functions/機能リスト.md` と `work/functions/items/` を書式の材料にしてはならない。
理由: 本スキルを使う時点で、その 2 つが存在するとは限らない。

**書式の参照とデータの参照は別である。** 既存の生成物をデータとして読んでよい場面は 8 つある。
場面は [../SKILL.md](../SKILL.md)「既存の生成物の扱い」の表にある。
既存の一覧へ行を足す場合も、書式は本フォルダの雛形を正とする。

## 共通の規則

- `<...>` の箇所を埋める。`<...>` を残したまま完了としてはならない。
- 該当が無い箇所は空欄にせず、「該当なし」または `—` と書く。
  理由: 空欄では「書き忘れ」と「該当なし」を判別できない。
- 節の見出しを消してはならない。追加してもよい。
  理由: `work/tools/check_functions.py` は必須の 9 節の見出しの有無を検査する。

## `機能リスト.md` を埋めるとき

既存の `機能リスト.md` がある場合、雛形をコピーしない。既存へ行を足す。
手順は [../SKILL.md](../SKILL.md) の工程 3 にある。以下の 5 手順は、新規に作る場合のものである。

**既存へ足す場合も、下の手順 3 と手順 4 と手順 5 は行う。**
集計を数え直し、着手条件の判定と根拠を書き直し、更新履歴に 1 行足す。
理由: 集計が変われば着手条件の判定も変わる。集計だけを直した場合、判定が古いまま残る。

1. 冒頭の案件名・正本のパス・作成日・入力を埋める。
2. 「一覧」の表に、1 機能につき 1 行を足す。
   `F-ID` の欄は `items/` の doc へのリンクにする。
   理由: `check_functions.py` はこの形の行だけを一覧の行として読む。
3. 「状態の集計」の件数を、一覧表を数えて書く。推定で書いてはならない。
   件数は算用数字で書き、`**` で囲む。理由: `check_functions.py` はこの形の行から件数を読む。
4. 「仕様設計書の着手条件」の判定と根拠を書く。
   条件を満たさない場合は、ブロッカーになっている `F-ID` と `Q-ID` を並べる。
5. 「更新履歴」に 1 行足す。

「読み方」の表と、3 種別の表は、そのまま残す。書き換えてはならない。
理由: この 2 つの表は、読み手が状態と種別の意味を引くための定義である。

## `item-template.md` を埋めるとき

1. 見出しの `F-xxx` と `<機能名>` を埋める。
2. ヘッダの 4 行（区分・状態・根拠 REQ・関連 QA）を埋める。
   `- 状態:` の行を消してはならない。
   理由: `check_functions.py` はこの行を読み、一覧の状態と一致するかを検査する。
3. 9 つの節を埋める。節ごとの材料は [../SKILL.md](../SKILL.md) の工程 5 の表にある。
4. テンプレに書いてある説明文（「〜してはならない」「理由: 〜」の行）は、埋めた後に消す。
   理由: 説明文は埋め方の指示であり、生成物の内容ではない。
5. 「更新履歴」に 1 行足す。

ファイル名は `F-xxx_<機能名>.md` とする。
`<機能名>` にスラッシュと空白を入れてはならない。理由: ファイル名とリンクが壊れる。
